# Диагностика и возврат на личный VPN

Приоритет: наш HTTPS/H2 → наш HTTPS/H1 → Blanc → Amnezia.
Менеджер `/opt/sbin/home-vpn-auto` запускается существующим cron раз в минуту
и при наличии `api-enabled` передаёт управление `/opt/sbin/home-vpn-priority`.

Домашний маршрут использует VLESS/XHTTP stream-up через HTTPS/H2 18447,
nginx → `127.0.0.1:18445` → отдельный `home-vpn-h2.service`.
Рабочий резерв того же VPS: HTTPS/H1 packet-up 443,
nginx → `127.0.0.1:18444` → `home-vpn-xhttp.service`.
Это резерв транспорта, а не независимый сервер. H2 использует отдельный
listener: включение H2 на общем 443 выявило несовместимость H1-клиента.
TLS-сертификат IP проверяется, `allowInsecure=false`. Старый Reality 8443
сохранён для существующих прямых клиентов. Личные `home-vpn.json` и
`home-vpn-probe.json` используют одинаковый новый транспорт; routing не менялся.
Короткий IP-сертификат продлевает существующий `signal-cert-renew.timer`
с проверкой и reload nginx. Mac-агент дополнительно предупреждает, если срок
сохранённого сертификата меньше 48 часов; проверяет раз в час, требует
доступного Mac и SSH к VPS, не заменяет проверку реально выдаваемого TLS.
Логи HTTP-пути VPN отключены, сервис пишет
только предупреждения в системный journal.

Приватные backup: роутер `/opt/var/backups/home-vpn-xhttp-20261002/`,
VPS `/root/vpn-repair-20261002/`. Проверяемые шаблоны без UUID:
`tools/home_vpn_xhttp.py`, `tools/home-vpn-xhttp.service`,
`tools/home-vpn-xhttp.nginx.conf`. Конвертер выводит секретный JSON;
его вывод сохранять только приватно на соответствующем устройстве.

Проверки используют SOCKS 10809, принудительно направленный через VPN:
YouTube `generate_204` и Cloudflare trace. В журнале есть HTTP-код,
код ошибки curl, время TCP/TLS/всего запроса и выходной IP.
Один недоступный сайт не отключает весь VPN. Два последовательных цикла,
в которых оба сайта недоступны, запускают поиск проверенного резерва. Ответ trace
с неправильным IP также считается ошибкой личного маршрута.

Все кандидаты загружены заранее. Локальные SOCKS-порты: 10821 основной,
10824 наш H1, 10822 Blanc, 10823 Amnezia. Проверки резервов идут раз в пять
минут, без смены пользовательского пути. При переключении кандидат должен
открыть оба сайта; для наших транспортов подтверждается `185.234.9.26`.
Мёртвый резерв не выбирается; если все пути недоступны, менеджер фиксирует
`all-paths-down` и сохраняет текущий путь без циклических перезапусков.

Переключение новых запросов идёт через локальный API `127.0.0.1:10085`,
`xray api bo -b home-priority TAG`, без рестарта Xray. API слушает только
loopback. После переключения снова проверяется фактический выход; при
ошибке API-выбор откатывается. Уже установленные здоровые соединения
не прерываются переключением; сломанное соединение клиенту нужно открыть заново.
Возврат на основной требует трёх успешных циклов и трёхминутной паузы.
После постороннего рестарта менеджер восстанавливает сохранённый API-выбор.

Старый Blanc cron выключен. Mac-обновитель меняет только сохранённый пул
под общим lock: не активный outbound, не cron и не выбранный маршрут.
Обновлённый файл пула не меняет уже загруженный outbound; новый рабочий
профиль нужно проверить и включить отдельно. По состоянию внедрения
оба наших транспорта работают, Blanc/Amnezia не прошли проверки.

Полный приватный backup API-миграции:
`/opt/var/backups/home-vpn-priority-20261002T044711Z/`.
В нём конфиги, личные профили, скрипты, cron и состояние. При полном откате
восстановить их вместе, убрать новый `07_home_api.json`/`api-enabled`, проверить
полный confdir и перезапустить только XKeen. Исторические backup H1 выше
относятся к предыдущему этапу. Не восстанавливать один outbound отдельно.

## Журналы

`/opt/var/log/home-vpn/rolling/` — скользящие последние 15 минут:
по минуте до 48 КиБ error.log, 16 КиБ access.log, 8 КиБ результатов проверок,
8 КиБ журнала изолированной проверки личного VPS
и небольшой снимок состояния. Это ограниченные фрагменты, а не полный
захват всего трафика. Старые минуты удаляются при следующем цикле.

Перед переключением/попыткой восстановления пулов этот буфер сохраняется
в `/opt/var/log/home-vpn/incidents/*.log.gz`. Результат операции — соседний
файл `.result`. При неудачном возврате отдельный снимок сохраняется до отката.
Хранятся не более восьми эпизодов и суммарно не более 8 МиБ архивов.
Общий объём диагностики обычно меньше 10 МиБ. До первых 15 минут работы
архив содержит только уже накопленные записи.

Исходные логи Xray ограничиваются раз в минуту: error.log до 256 КиБ,
access.log до 128 КиБ. Между проверками они могут временно превысить лимит.
Сохраняется inode открытого Xray файла; параллельная запись во время
усечения может потерять несколько строк. Снимок снимается до усечения.
Конфиги, ключи и тела пользовательских запросов в архив не копируются;
сетевые логи содержат локальные адреса и посещаемые домены и остаются приватными.

```sh
ssh root@192.168.1.1 /opt/sbin/home-vpn-auto status
ssh root@192.168.1.1 'ls -lt /opt/var/log/home-vpn/incidents'
ssh root@192.168.1.1 'gzip -dc /opt/var/log/home-vpn/incidents/ИМЯ.log.gz'
```

Исходники: `tools/home-vpn-priority.sh`, `tools/home_vpn_priority.py`,
`tools/home-vpn-auto.sh`, `tools/home-vpn-log.sh`.
Проверки: `python3 tools/test_home_vpn_priority.py`,
`python3 tools/test_home_vpn_auto.py -v`.
Установка: `sh tools/install-home-vpn-monitor.sh`.
Установка сохраняет точный backup скриптов, состояния, активного outbound,
cron и log-конфига на самом роутере, проверяет конфигурацию и не перезапускает Xray.
Cron и маршруты установки не изменяются.

Для отката остановить запуск менеджера через его lock, восстановить скрипты
из выданного каталога backup (старый менеджер не использует новый журнал),
освободить lock. Outbound и состояние восстанавливать только если нужен
откат именно маршрута, затем проверить конфигурацию и перезапустить только XKeen.
