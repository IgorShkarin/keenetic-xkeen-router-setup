# XKeen на роутере: команды из Terminal

Эта шпаргалка предназначена для Mac в домашней сети Netcraze/Keenetic.
Управление XKeen выполняется через Entware SSH: `root@192.168.1.1`, порт `22`.

> Встроенный SSH самого Netcraze работает отдельно на порту `2022` под
> пользователем `admin`. Команды `xkeen` нужно запускать не там, а через
> Entware SSH на порту `22`.

## Быстро выключить VPN на роутере

Подключить Mac к домашнему Wi-Fi и выполнить:

```bash
ssh root@192.168.1.1 'xkeen -stop; xkeen -status'
```

Ожидаемый итог:

```text
Прокси-клиент не запущен
```

Это останавливает только XKeen/Xray. Роутер не перезагружается, конфигурация
VLESS не удаляется.

## Включить VPN на роутере

```bash
ssh root@192.168.1.1 'xkeen -start; xkeen -status'
```

Ожидаемый рабочий режим после запуска: `Hybrid`.

## Перезапустить только XKeen

```bash
ssh root@192.168.1.1 'xkeen -restart; xkeen -status'
```

Это не перезагрузка роутера. Использовать перезапуск только после изменения
конфигурации или при отдельной необходимости.

## Проверить статус

```bash
ssh root@192.168.1.1 'xkeen -status'
```

## Проверить конфигурацию Xray без запуска

```bash
ssh root@192.168.1.1 'xkeen -xtest'
```

Если проверка сообщает об ошибке, не запускать и не перезапускать XKeen до её
устранения.

## Версия и справка

```bash
ssh root@192.168.1.1 'xkeen -v'
ssh root@192.168.1.1 'xkeen -h'
```

На 1 сентября 2026 года live-проверкой были подтверждены:

- XKeen `2.0 Stable`;
- Xray `26.6.27`.

Версии могут измениться после обновления, поэтому при диагностике проверять их
заново.

## Автозапуск после перезагрузки роутера

Отключить автозапуск:

```bash
ssh root@192.168.1.1 'xkeen -auto off'
```

Включить автозапуск:

```bash
ssh root@192.168.1.1 'xkeen -auto on'
```

Это постоянная настройка. Для обычного временного отключения использовать
`xkeen -stop`, не менять автозапуск.

## Посмотреть последние логи

Лог запуска XKeen:

```bash
ssh root@192.168.1.1 'tail -n 80 /opt/var/log/xkeen-detached.log'
```

Ошибки Xray:

```bash
ssh root@192.168.1.1 'tail -n 80 /opt/var/log/xray/error.log'
```

Последние маршруты Xray, если access-log включён:

```bash
ssh root@192.168.1.1 'tail -n 80 /opt/var/log/xray/access.log'
```

Логи не очищать. Длительный постоянный мониторинг без необходимости не
включать.

## Перед подключением: проверить домашнюю сеть

Текущий IP Mac:

```bash
ipconfig getifaddr en0
```

Для доступа к роутеру ожидается адрес вида `192.168.1.x`.

Проверить роутер:

```bash
ping -c 3 192.168.1.1
curl -I --connect-timeout 3 http://192.168.1.1/
nc -vz -w 3 192.168.1.1 22
nc -vz -w 3 192.168.1.1 2022
```

## Если появляется ошибка

### `No route to host` или `ERR_ADDRESS_UNREACHABLE`

Mac не может дойти до локального адреса роутера. Проверить:

1. Mac подключён именно к домашнему Wi-Fi, а не к мобильной точке.
2. `ipconfig getifaddr en0` показывает `192.168.1.x`.
3. Tailscale или другой локальный VPN не перехватил маршрут `192.168.1.0/24`.
4. Попробовать домашнюю сеть 2,4 ГГц: в последней проверке она дала рабочий
   доступ, тогда как на 5 ГГц сначала возникал `No route to host`.

Посмотреть текущий маршрут:

```bash
route -n get 192.168.1.1
```

В рабочем состоянии должен быть указан локальный Wi-Fi-интерфейс `en0`, а не
`utun`.

### Порт `22` отвечает `Connection refused`

Entware/OPKG или его SSH-сервер не запущен. Порт `2022` может при этом работать,
но это встроенный CLI Netcraze, в котором команды `xkeen` недоступны. Не
перемонтировать OPKG и не перезагружать роутер вслепую: сначала проверить
состояние OPKG через админку или встроенный CLI.

### XKeen остановлен, но десктопный VPN всё равно не работает

Значит, одного роутерного VLESS недостаточно для объяснения сбоя. Проверять
десктопный VPN, его DNS, маршрут и `utun` отдельно; не менять конфигурацию Xray
без свежих доказательств.

## Подключиться к оболочке вручную

Entware/XKeen:

```bash
ssh root@192.168.1.1
```

Встроенный CLI Netcraze (не для команд XKeen):

```bash
ssh -p 2022 admin@192.168.1.1
```
